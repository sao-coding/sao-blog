# 影の書庫 · 設計風格指南

新增頁面、元件、動畫之前先讀這份。文章內的區塊元件另有細則：[`src/components/mdx/DESIGN.md`](src/components/mdx/DESIGN.md)（「紙上之物」）。
改造的執行順序與進度在 [`REDESIGN-PLAN.md`](REDESIGN-PLAN.md)。

## 一句話

**由遠而近的一幅水墨：遠是夜裡的江山，中是枯山水的庭，近是案上的一張信箋；全站跟著二十四節氣過日子。**

構圖取自郭熙的「三遠」：首頁是江山的遠景，要有氣魄；往裡走是庭，安靜、可以久留；
走到最近是一張信紙，只剩字。越往裡越近、越靜、越專心讀。

枯山水「以砂代水」、水墨「以墨借水」——都是在沒有水的地方畫出水。江上的水流進庭裡成了砂，
這是中與和在這個站的接點。

## 0. 字層與畫層

每一頁分兩層：

| 層 | 是什麼 | 規則 |
|---|---|---|
| **字層** | 讀者真正在用的 UI：列表、標題、日期、摘要、按鈕、表單 | 照一般的可讀性與無障礙做：一列一篇、可點、可鍵盤操作、手機好讀。**不因為比喻改版面或資訊結構** |
| **畫層** | 字層後面的一張畫（WebGL／canvas／SVG）：江山、庭、砂紋、霧 | 純氛圍：`aria-hidden`、不可聚焦、整層關掉也不影響使用；窄螢幕可以只留一角 |

- **畫層是整體的景，不是資料圖表**：不把一篇文章、一位朋友、一則留言各畫成畫裡的一個物件。
  畫層表現的是「這是哪一處、現在是什麼節氣」，不是「這裡有幾篇文章」。
- 字層該有的資訊（日期、字數、留言數）照樣用文字寫出來。

## 1. 三遠：由遠而近

| 遠近 | 頁面 | 畫層 | 氣氛 |
|---|---|---|---|
| **遠：江山** | 首頁 | 既有的 **3D 夜航水墨山水**（`ink-voyage.ts`）：群山、江面、烏篷船與燈籠倒影；水中一座朱色鳥居（全站唯一的大面積高彩度物件，夜裡燈籠映在它身上） | 有氣魄、可以帥：整站唯一允許大場面、大動態的地方 |
| **中：庭** | 列表與索引頁（文章、分類、筆記、專欄、碎念、時間線、友鏈、朋友圈） | 枯山水的庭：砂紋、石組、苔、竹、牆外遠山。各頁是庭裡不同的一隅（見第 4 節） | 安靜、留白多；動態只有砂紋與霧的緩慢變化 |
| **近：案頭** | 文章、筆記內頁 | 幾乎沒有畫，只有紙（`letter-paper` 信箋）與文末的干支落款 | 最靜：只剩字 |

- 往裡走（首頁 → 列表 → 文章）是**由遠推近**；往外走是拉遠。轉場照這個方向做（第 5 節）。
- 江與庭是連著的：從首頁往裡走時，鏡頭順江往鳥居推近，紙色漫上來、庭的砂紋淡入，接上列表頁的庭。（試過推近時從江面畫一道遣水接到砂紋，看不出在做什麼，已拿掉。）

## 2. 三樣材料

| 材料 | 是什麼 | token |
|---|---|---|
| **紙** | 底。晝是宣紙（淺、暖、低彩度、有纖維），夜是燈下的紙（深藍黑，紙紋仍在） | `--background` / `--card`、`--paper-texture` |
| **墨** | 字、筆觸、暈染。墨有**乾濕**與**濃淡**，可以是線，也可以是暈開的面 | `--foreground`、`--rule`，濃淡用 `color-mix(--foreground N%, --background)` |
| **朱** | 唯一的強調色：鳥居、落款、強調、目前所在 | `--ink`（歷史命名，就是朱） |

- **節氣色 `--season`**（`lib/term-themes.ts`，24 個）是「季節的那一抹」，染在墨與霧裡：進度條、霧與月暈的染色、目前節氣的小標記；不用在大面積底色。冬天的節氣色接近白，任何用到它的設計都要在冬至檢查一次。
- 朱是中國的印泥色，也是日本鳥居的顏色，兩種文化同一個朱，不另開紅色。
- `--jade` 只留給既有的成功／已完成狀態，不用在新設計。
- 字：標題與人話用霞鶩文楷 TC（`font-wenkai`），技術資訊用 mono。中文不加粗表現強調，用朱或字距；大標可直排（`writing-mode: vertical-rl`）。

## 3. 三條規則

### 規則一：墨分乾濕——新的濕，舊的乾

文章的新舊表現在**字層標題的墨色**上，不靠畫層：

| 時間 | 標題的墨 |
|---|---|
| 這個節氣寫的 | **濕墨**：濃一階，滑過時邊緣有極淡的暈（`text-shadow` 用墨色、低透明度），像剛寫上去 |
| 今年寫的 | 乾墨：正常濃淡 |
| 更早 | 淡一階的墨 |

- 「濕」只是質感，字一律清楚可讀，不真的模糊；對比度仍要過 WCAG AA。
- 乾濕的換算只看發文時間與目前節氣（`lib/season.ts` 的 `getSolarTerm`），不看點閱、不看熱門度。
- 滑過列表某一列時，那一列的標題墨變濕（暈一下）——互動回饋在字層本身完成，不牽動畫層。

### 規則二：筆有起收——線是筆觸，面是暈染

- 畫層與主視覺的線要有起筆、行筆、收筆，粗細有變化（藏鋒、出鋒），不用等粗的幾何線；字層的分隔線可以用 1px 髮絲線。
- 要有「面」時用**暈染**（墨在紙上化開，`lib/ink-fluid.ts` 那一套），不用平塗色塊、不用 CSS 漸層底；毛玻璃只用 `.glass`（常駐的面）與 `.glass-strong`（浮在內容上的面）兩階，定義在 styles.css，不在元件裡自己拼 `backdrop-blur`。首頁 3D 山水的墨韻屬於暈染。
- 陰影只給真的浮起來的東西（相片、信紙疊層）。
- 日式元素用筆觸與留白表現（砂紋、障子格、暖簾垂線、青海波）；不用浮世繪、櫻花滿版、和柄花紋鋪底；不用印章當主要視覺。

### 規則三：景隨節氣——構圖固定，季節在換

- 每一處的構圖固定（山、江、石、牆的位置不動），**換的是季節**。
- 四季的山水設色：春「青綠」、夏「濃墨」、秋「淺絳」、冬「雪景」；白露／寒露／霜降霧較濃。
- 庭的砂紋**每個節氣重耙一次**：二十四種耙紋輪流（直紋、波紋、青海波、渦紋……），同一個節氣裡每次打開都一樣，不隨機。苔色跟著季節走。
- 物候飄落物（梅、櫻、油桐、鳳凰花、欒樹、楓、雪……，見 `term-themes.ts`）只在首頁的江山裡，同一時間以一兩種為主。

## 4. 頁面對照

「畫層」一欄描述的是該頁背後的那一處景；字層照各頁原本的列表／內文做。

| 頁面 | 路由 | 遠近 | 畫層 |
|---|---|---|---|
| 首頁 | `/` | 遠 | 3D 夜航江山（見第 1 節），只留水面互動：滑過水紋、點擊漣漪 |
| 文章列表 | `/posts` | 中 | 庭的正面：這個節氣的耙紋與一組石 |
| 分類 | `/categories/$slug` | 中 | 庭的一隅：每個分類固定一處（石組、竹叢、蹲踞、石燈籠……），由分類 slug 決定 |
| 筆記（手記） | `/notes` | 中 | 苔庭：庭裡最安靜、最私人的一角 |
| 專欄 | `/notes/topics`、`/$slug` | 中 | 飛石小徑：一條通往深處的踏腳石路 |
| 碎念 | `/thinking` | 中 | 竹枝與風：竹葉偶爾晃一下；字層每則可以用短冊的直條造型 |
| 時間線 | `/timeline` | 中 | 遣水：從江引進庭的一道細流，由上游（最早）往下游（現在） |
| 友鏈 | `/friends` | 中 | 借景：庭牆外的遠山 |
| 朋友圈 | `/fcircle` | 中 | 牆頭：從牆外探進來的枝，偶爾落一片葉 |
| 文章 | `/posts/$slug` | 近 | 信箋：既有的 `letter-paper`，文末落款「干支年 節氣」（`lib/ganzhi.ts`） |
| 筆記內頁 | `/notes/$id` | 近 | 同一張信箋，紙色淡一階 |
| 留言 | 文章底部 | 近 | 絵馬造型的留言框；站主回覆用朱落款 |
| 登入 | `/login` | — | 暖簾：撥開才進去 |
| 404 | — | — | 霧裡的鳥居：一座通往霧裡的鳥居，後面什麼都沒有 |
| 載入 | — | — | 円相：一筆畫的圓 |

- 新頁面要先在這張表加一列再開工：先決定它在遠、中、近哪一層，再決定是哪一處景。
- 一個畫面最多一座鳥居。

## 5. 轉場：推近、拉遠、暈染

依頻率決定強度——越常發生越輕：

| 時機 | 做法 | 實作 |
|---|---|---|
| 整頁載入（重新整理／從外部進站） | 墨暈開場：節氣名 → 墨滴落下 → 被水沖淡 | `components/ink-intro.tsx`、`lib/ink-fluid.ts` |
| 首頁 ⇄ 列表（遠 ⇄ 中） | 同列表之間：舊內容很快淡掉，往列表時列表逐行進場；回首頁交給 hero（原本的推近已拿掉，見 REDESIGN-PLAN 階段 8） | 同下 |
| 列表 ⇄ 列表（中 → 中） | **庭不動，只有字進出**：舊內容 0.1s 淡掉；新頁標題先出、列一行一行跟上（每行 32ms，整體 < 400ms），只用 opacity 與小幅位移。換頁不等動畫 | `routes/_layout/route.tsx`、`lib/page-enter.ts`、`lib/post-transitions.ts`（type `list`） |
| 列表 ⇄ 文章（中 ⇄ 近） | 既有的**展卷／收卷**（View Transitions：標題飛行＋由上展開） | `lib/post-transitions.ts`、styles.css「展卷」 |
| 文章之間 | 既有的**翻頁** | 同上 |
| 往外走（近 → 中 → 遠） | 反向：收卷；回首頁同首頁 ⇄ 列表 | — |
| 換頁慢於 300ms | 頂端節氣色毛筆一筆 | `components/ink-progress.tsx` |
| 篩選、分頁、切語系 | 不做轉場，只淡入 | — |

規則：
- 一般過場 150–500ms、ease-out；儀式性動畫（開場、推近、展卷）可到 0.6–1.2s，但**不可阻擋操作**——一碰螢幕、捲動、按鍵就直接跳到結果。
- 互動要克制：一個場景最多一兩種，且必須是那處景裡會發生的事（江面漣漪 ✓、竹葉被風吹動 ✓，滿天亂飛的粒子 ✗）。
- `prefers-reduced-motion: reduce`：關掉位移、暈染與開場，只留淡入淡出。
- 3D / WebGL / canvas 一律在載入完成、主執行緒空閒後才建立（`lib/after-load.ts` 的 `afterLoadIdle`），不可見時暫停，離開時釋放並移除 canvas。

### 規格檔

季節相關的換算（這個節氣用哪種耙紋、苔色、霧的濃度、標題的乾濕）放在一份只有數字與純函式的檔案 `src/lib/season-spec.ts`（待建），首頁、庭、OG 圖都呼叫它，畫出來才一致。不碰 React、不碰 canvas；需要變化時用節氣序號或 slug 做種子，不用 `Math.random()`。

## 7. 參考其他站的分寸

可以參考別人的站（例如 koimsurai「宙と木」），但**做出來不要太像**：
- 這個站原本就有的東西（節氣、墨暈、3D 夜航、展卷、信箋落款、朱、鳥居）是自己的，照用。
- 工程作法可以直接學：共用規格檔、token 檢查、確定性的種子、先用文字寫出比喻再寫程式。
- 要避開的是別人的**招牌做法**。以宙と木為例：把每一篇文章、每一位朋友畫成背景裡的一個物件、物件大小對應數據；整頁收成一點再飛到下一頁長出來的轉場；夜空與星體的意象。
- 新增設計時先問：拿掉配色與題材之後，這個做法是不是跟某個參考站一樣？是的話就換一個從水墨或日式庭園推出來的做法。
